# MuJoCo 4.0.1 原生 SDK 升级验证报告

状态：SDK 编译、打包、独立消费者与搬移后 USD 验证完成。原始日期：2026-11-16。仿真应用的任务、传感器与真实 GPU 场景验收由仿真仓库另行记录，本报告不代替这些验收。

## 版本与构建

- MuJoCo 官方 `4.0.1`：`4ed093a9f06b170bd1564942fa37e1bb907d93e3`。
- OpenUSD `v25.11`：`363a7c8da8d1937072a5f0989e91faf72eb1fa76`。
- Filament：`0643fd0f4363b85295fcaccd067a042072e483dd`，由 MuJoCo 固定。
- 系统：Ubuntu 20.04.6 / glibc 2.31；编译器：Clang 18.1.8（11~20.04.2），使用 GCC 11 的 libstdc++ 头文件和原生 USD string ABI。
- SDK 所有动态库的最高 GLIBC 符号要求为 **2.29**；未混入 Ubuntu 24.04 构建的库。
- `MUJOCO_WITH_USD=ON`、`MUJOCO_USE_FILAMENT=ON`、`MUJOCO_USE_FILAMENT_MJR_COMPAT=OFF`；关闭 LTO，不需要 Python 运行时。
- 完整 MuJoCo 补丁 SHA-256：`2885e998cb2fc63cbfa287e0f493212f8df0c1fc6bf598b90f1b34e85cba15b1`。原工程子模块差异、`patches/mujoco-4.0.1.patch` 与包内补丁一致。

本轮复用原工程的 Ubuntu 20.04 OpenUSD 完整安装，全部 MuJoCo/Filament 对象使用 Clang 18 重编。GCC 11 和 Clang 12 的探索构建未成为交付制品；其编译器专用 Filament 修改已撤销。现行重建入口为根目录 `scripts/build_baseline.sh`。

提交前核对发现默认 `ubuntu:20.04` 镜像不含 CA 证书。Dockerfile 已调整为先从 Ubuntu HTTP 软件源安装证书，再启用 LLVM HTTPS 源；此修复不改变已验证 SDK 的工具链和二进制。
