# SDK 架构说明

## 目标与边界

提供不依赖 Python 进程的 MuJoCo 4.0.1 C++ 物理、OpenUSD 25.11 导入与 Filament 三维渲染能力。SDK 只负责库和资源；ROS、飞控、规划器、TCP 控制接口及仿真场景由使用方维护。

平台固定为 Ubuntu 20.04 / x86_64，保留 AVX 要求。编译采用 Clang 18 与 GCC 11 的 libstdc++ 头文件，动态 C++ 运行库随 SDK 打包；glibc、X11/OpenGL、Vulkan loader（例如 `libvulkan1`）和 GPU ICD/驱动使用系统提供的版本。三维渲染使用 Vulkan，二维 UI 使用 OpenGL。禁止混入在新版本 Ubuntu 上编译、要求更高 GLIBC 的库。

## 输入与构建流程

1. MuJoCo 子模块固定官方 `4.0.1`：`4ed093a9f06b170bd1564942fa37e1bb907d93e3`。
2. OpenUSD 子模块固定 `v25.11`：`363a7c8da8d1937072a5f0989e91faf72eb1fa76`，采用 shared、无 Python、无 imaging 构建。
3. `scripts/build_baseline.sh` 核对 MuJoCo 提交，检查并应用 `patches/mujoco-4.0.1.patch`；补丁已应用时不重复修改。
4. `docker/Dockerfile.ubuntu20.04` 先通过 Ubuntu HTTP 软件源安装 CA 证书，再启用 LLVM HTTPS 软件源，避免干净 Ubuntu 镜像缺少证书导致首次索引下载失败；随后准备 Clang 18、GCC 11 标准库、CMake、X11/OpenGL 开发依赖与打包工具。LLVM 软件源签名文件来自 `https://apt.llvm.org/llvm-snapshot.gpg.key`。
5. `cmake/Dependencies.cmake` 构建原生 OpenUSD，然后构建 MuJoCo。可通过 `SWARM_USD_ROOT` 复用相同平台、版本、编译 ABI 的完整 USD 安装；不能复用宿主机新 GLIBC 的构建。
6. `scripts/package_sdk.py` 复制库、头文件、shader 与 USD schema，修正相对运行路径，记录版本/补丁/许可证，检查全部动态依赖和 GLIBC 基线。

首次构建会下载 MuJoCo 固定的 Filament `0643fd0f4363b85295fcaccd067a042072e483dd`。Shader 编译工具只用于构建，不要求用户运行 Python 或在线下载。

## 渲染与 USD 契约

`MUJOCO_USE_FILAMENT=ON`、`MUJOCO_USE_FILAMENT_MJR_COMPAT=OFF`。正式三维场景通过官方 `mjrf` 和 ModelResources/ModelRenderables 等缓存渲染；Simulate 的二维 UI 仍使用其原有 classic 接口，不保留两个三维渲染后端供切换。

MuJoCo 的实验 `mjr` 兼容入口不能完成现有 Simulate 的二维 UI，因此补丁在官方 Simulate 入口使用 Filament 三维输出，并保留面板、文字、输入处理。模型资源在模型加载或显式资源更新时建立，正常帧更新位姿。

Filament shader 位于 `share/mujoco/filament/`。Simulate 资源提供器根据实际加载的 `libmujoco` 定位该相对目录，不能将构建机绝对路径写入应用。

OpenUSD 使用 C++ 原生安装的默认 string ABI。补丁去除上游针对 Python wheel 固定旧 ABI 的假设，保留原生 pxr 目标定义，并修复 MuJoCo 作为 CMake 子工程时 Dear ImGui 的源目录定位。

## 输出与接入

SDK 目录必须整体搬移，包含：

- `include/`：MuJoCo、Simulate、GLFW、OpenUSD 公开头文件。
- `lib/`：MuJoCo、USD、TBB、插件和 C++ 运行库；每个动态库通过 `$ORIGIN` 查找同目录依赖。
- `lib/filament/`：此次实际构建的静态库；CMake 链接组解析其循环依赖，不增加自定义二进制包装层。
- `lib/usd/` 与 `lib/mujoco-usd-resources/`：USD 插件信息和 schema。
- `share/mujoco/filament/`：材质与环境资源。
- `lib/cmake/SwarmMuJoCoSDK/`、`pxrConfig.cmake`：可搬移开发导出。
- `licenses/`、`source-patches/`、`VERSION.json` 和 `SHA256SUMS`：归属、实际补丁和可核验版本。

主导出为 `mujoco::mujoco`、`mujoco::libmujoco_simulate`、`mujoco::filament`、`glfw` 与 `usd_decoder_plugin`。应用不应直接依赖构建目录中的内部路径。

## 验证边界

打包检查不能替代运行验证。发布前必须至少完成：C++17 消费者链接全部正式目标；搬移目录后以 C++ USD API 与 MuJoCo decoder 读取 USD 并执行物理步进；检查不依赖 Python、旧源码目录或缺失动态库；在实际 GPU 上验证 Filament、原有二维 UI 与仿真控制链路。每次验证使用本次构建制品，不以旧版本记录代替。
